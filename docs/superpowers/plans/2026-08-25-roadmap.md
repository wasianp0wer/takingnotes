# Note Capture App — Plan Roadmap

**Spec:** `docs/superpowers/specs/2026-08-25-note-capture-app.md`

The work is split into six plans. Each produces working, independently testable
software and can be reviewed and merged on its own. Phases 1A and 1B are
independent of each other and may be worked in parallel or in either order.

---

## Plan 1A — Storage foundation

**File:** `docs/superpowers/plans/2026-08-25-phase-1a-storage.md`
**Covers task:** #3
**Depends on:** nothing

Establish test infrastructure (none exists today) and an IndexedDB-backed
storage layer for notes, pages, rendered images, transcripts, and settings.
Migrate existing `localStorage` notebooks.

**Exit criteria:** `npm test` runs and passes; a note with pages and a Blob
render survives a database round-trip; existing `localStorage` notebooks import
without loss; the studio app is unchanged.

---

## Plan 1B — Device foundation

**File:** `docs/superpowers/plans/2026-08-25-phase-1b-device.md` *(not yet written)*
**Covers tasks:** #4, #5, #6
**Depends on:** 1A (test infrastructure only)

Make the Huion driver testable and reusable: extract pure protocol helpers,
introduce an injectable transport so the driver can be exercised without
hardware, add `getStoredPageCount()` and `downloadPage(n)`, implement the
declared-but-unsent `DELETE_PAGE`/`CLEAR_CACHE` commands, and expose the device
through a provider with multi-subscriber event fan-out.

**Why fan-out matters:** `HuionNoteBLE` exposes single-slot callbacks
(`onPen`, `onLog`, `onNextPage`). In Phase 2 both the live preview and the
session recorder need pen points; without fan-out the second consumer silently
clobbers the first.

**Exit criteria:** protocol helpers unit-tested; driver drivable by a fake
transport in tests; single-page download works against hardware; delete
commands verified against hardware but wired to no UI.

## Plan 2 — Session engine

**File:** *(not yet written)*
**Covers tasks:** #7, #8, #9, #10, #18
**Depends on:** 1A, 1B

Steps 1–3 of the workflow. Session state machine, live capture buffer, page
baseline anchoring, incremental per-page download on page turn (per finding
C1/C2), interruption detection and resume, page reconciliation, stroke→PNG
rendering, and the confirm-before-clearing dialog.

**Exit criteria:** start → write → interrupt → resume → complete produces a
correct multi-page note with rendered images.

## Plan 3 — Inference

**File:** *(not yet written)*
**Covers tasks:** #11, #12, #13, #17
**Depends on:** 1A, 2. Informed by #1 (transcription quality harness).

Steps 4–5. Ollama client, model discovery and capability detection, setup and
diagnostics flow, transcription and summarization, and a strictly sequential
resumable job queue.

**Exit criteria:** a completed note transcribes to markdown and summarizes
against local Ollama; the queue survives reload; a note stays browsable while
transcription is pending or partially failed.

gates model selection and realistic per-page timing, so it should be run before
Plan 3 is specced in detail.

live-streaming is unresolved. It does not block 1A or 1B, and the
reconciliation design in Plan 2 is correct either way, but settling it will
